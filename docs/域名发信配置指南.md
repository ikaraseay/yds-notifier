# 用你的域名发信：Resend 接入指南

只有域名、没有邮箱服务器，也能让通知邮件显示为 `研电赛通知 <notice@你的域名>`。
原理：**你不需要自己跑邮件服务器**。Resend 代你投递，用 DNS 里的 DKIM 记录证明"这封邮件确实是你的域名发出来的"。

---

## 一、先搞清三件事

| 概念 | 需不需要自己搭 | 说明 |
|---|---|---|
| **发信（SMTP）** | 不需要 | 由 Resend 代发，走 HTTPS 443，GitHub Actions 不会被端口封锁影响 |
| **收信（MX）** | 不需要 | `notice@你的域名` 只作发件人显示，不接收回信。想收信可加 Cloudflare Email Routing（免费） |
| **域名验证** | 需要 | 在 DNS 加几条 TXT/CNAME 记录，一次性 5 分钟 |

> 不要试图在 GitHub Actions 里跑 Postfix：Actions 的运行机没有固定公网 IP、不开放 25 端口、每次运行都是新机器，收信和直连发信在原理上就不可能。

---

## 二、本项目当前配置：站点用子域、发件用根域

| 项 | 值 |
|---|---|
| 站点 / 订阅页 / 退订链接 | `https://notice.example.com`（Workers Custom Domain） |
| 发件人 | `研电赛通知 <notice@example.com>` |
| **Resend 里要验证的域名** | **`example.com`（根域，不是 `notice.example.com`）** |
| DNS 托管 | Cloudflare，zone `example.com` |
| 配置项 | `.env` → `MAIL_FROM_ADDRESS="notice@example.com"` |

**发件域名与站点域名是两回事**：`CUSTOM_DOMAIN` 只决定页面与邮件里链接的地址，
`MAIL_FROM_ADDRESS` 只决定邮件 From 头。Resend 验证 `example.com` 之后，该域下**任意地址**
（包括 `notice@example.com`）都能作为发件人，不需要在 Resend 里创建这个邮箱，也不需要给它配 MX 收信。

> Resend 官方推荐用子域（如 `mail.example.com`）发信以隔离发信声誉；本项目按需求用根域，
> 功能完全正常，代价是根域的所有发信共用同一声誉、DMARC 策略作用于整个根域。
> 当前 `example.com` 没有任何 MX / SPF / DKIM / DMARC 记录，属于干净状态，直接加即可，无冲突。

---

## 三、操作步骤

### 1. 注册 Resend 并添加域名

1. 打开 [resend.com](https://resend.com) 注册（GitHub 账号可直接登录）
2. 左侧 **Domains → Add Domain**，域名填**发件域 `example.com`**；Region 选靠近收件人的区域；
   Return-Path 保持默认 `send.example.com` 即可
3. 打开该域名的 **Records** 标签，把列出的记录逐条加到 Cloudflare。通常是 3～4 条：

| 类型 | Cloudflare 里的名称 | 值（以 Resend 控制台为准） | 用途 |
|---|---|---|---|
| TXT | `resend._domainkey` | `p=MIGfMA0GCS...`（很长一串） | **DKIM** 签名，最关键 |
| TXT | `send` | `v=spf1 include:... ~all` | **SPF**，声明谁有权代你发信 |
| MX | `send` | `feedback-smtp.<region>.amazonses.com`，优先级 10 | Return-Path，接收退信 |
| TXT | `_dmarc` | `v=DMARC1; p=none; ...` | **DMARC**，验证通过后再加 |

**Cloudflare 填写要点**

- 名称只填前半段（`resend._domainkey`、`send`、`_dmarc`），Cloudflare 会自动补 `.example.com`；
  如果验证的是子域，名称要相应变成 `resend._domainkey.mail`、`send.mail` 等
- 这几条记录一律选 **DNS only（灰云）**，不能开代理，否则 Resend 验证不过
- 值**原样复制粘贴**，不要手动加引号或空格
- 若根域已有 SPF 的 TXT 记录，**不要新建第二条**，把 Resend 的 `include:` 合并进已有那条
  （一个域名只能有一条 SPF）

### 2. 在 Cloudflare 添加记录

`example.com` 已托管在 Cloudflare。进入 **Dashboard → example.com → DNS → Records → Add record**，
按上表逐条添加，TTL 用 Auto，代理状态保持 **DNS only**。

> Workers 的 `notice.example.com` 记录由 Wrangler 自动创建，**不要改动**；
> 邮件相关的 `send` / `resend._domainkey` / `_dmarc` 也不要开橙云代理。

### 3. 回 Resend 点 Verify

记录添加后点 **Verify DNS Records**，通常 1～15 分钟通过（极端情况最多 72 小时）。
验证通过后，`example.com` 下的任意地址都能作发件人，本项目用 `notice@example.com`。

### 4. 创建 API Key

Resend 左侧 **API Keys → Create API Key**，权限选 **Sending access**，域名选刚验证的
`example.com`。复制得到的 `re_xxxxxxxx`（**只显示一次**）。

### 5. 填写配置并同步两端

1. 把 `re_...` 填进根目录 `.env` 的 `RESEND_API_KEY`
2. 确认 `MAIL_FROM_ADDRESS="notice@example.com"`（本项目已设置好）
3. 一条命令同步 Cloudflare 与 GitHub：

```bash
bash scripts/ops.sh secrets --dry-run   # 先预览会写哪些键
bash scripts/ops.sh secrets             # 同步两端
```

脚本从 `.env` 读取、自动跳过空值，密钥只经 stdin / 临时文件传递，不打印明文。
只同步一端用 `bash scripts/ops.sh cf-secrets` 或 `bash scripts/ops.sh gh-secrets`。
GitHub 侧需要 `gh auth login --web --scopes "repo,workflow"` 且仓库已创建；
只想同步 Cloudflare 时用 `--target cf`。

也可以手工填：GitHub → `Settings → Secrets and variables → Actions`，
Cloudflare → Worker `Settings → Variables and Secrets`：

| 名称 | 值 |
|---|---|
| `RESEND_API_KEY` | `re_...`（Secret） |
| `MAIL_FROM_ADDRESS` | `notice@example.com` |
| `MAIL_TO` | `you@example.com` |
| `MAIL_FROM_NAME` | `研电赛通知`（可选） |

完整清单见 [Cloudflare自动部署指南](Cloudflare自动部署指南.md) 第三节。

> `config.yaml` 不含任何发信配置，无需改动；发信相关项全部走 `.env` / Secrets。
> 变量优先级：CI/Cloudflare 注入的环境变量 > `.env` > 内置默认值。

### 6. 测试

Actions 页面 → 选中「研电赛通知推送」→ **Run workflow**，输入框填 `normal` 运行。
日志里应看到：

```
发信通道：resend（研电赛通知 <notice@example.com>）
Resend 已投递 -> you@example.com（id=...）
```

## 五、常见问题

**Q：验证一直 pending？**
用 `dig TXT resend._domainkey.example.com +short` 检查记录是否已生效。DNS 缓存未过期是最常见原因，等 10 分钟再点 Verify。若记录开着 Cloudflare 代理，也会一直不通过。

**Q：邮件进了垃圾箱？**
1. 确认 `_dmarc` 那条 TXT 已加；
2. 若域名是新注册的，前几天会有"域名太新"的降权，正常现象；
3. 在收件箱把发件人加入白名单。

**Q：能收信吗？**
`notice@example.com` 只是发件人身份，别人回复会进不了任何邮箱。想接回信：
用 [Cloudflare Email Routing](https://developers.cloudflare.com/email-routing/)（免费）加一条 MX → 转发到你的 QQ 邮箱，两步搞定。

**Q：Resend 挂了怎么办？**
把 `.env` 的 `MAIL_PROVIDER` 改成 `smtp`（CI 上改同名 Secret），再填 `SMTP_USER` / `SMTP_PASSWORD` 即可切回邮箱授权码模式，代码无需改动。

**Q：能用其他服务商吗？**
可以，修改 `yds/senders.py` 里 `ResendSender.ENDPOINT` 与请求体即可适配 Brevo / Mailgun / 阿里云邮件推送。国内收件多时，阿里云 DirectMail 的国内送达率会更好（需域名备案）。
