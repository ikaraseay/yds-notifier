# 用你的域名发信：Resend 接入指南

只有域名、没有邮箱服务器，也能让通知邮件显示为 `研电赛通知 <notice@你的域名>`。
原理：**你不需要自己跑邮件服务器**。Resend 代你投递，用 DNS 里的 DKIM 记录证明"这封邮件确实是你的域名发出来的"。

---

## 一、先搞清三件事

| 概念 | 需不需要自己搭 | 说明 |
|---|---|---|
| **发信（SMTP）** | 不需要 | 由 Resend 代发，走 HTTPS 443，GitHub Actions 不会被端口封锁影响 |
| **收信（MX）** | 不需要 | `notice@你的域名` 只作发件人显示，不接收回信。想收信可加 Cloudflare Email Routing（免费） |
| **域名验证** | 需要 | 在 DNS 加几条 TXT/CNAME 记录，一次性 5 分钟 |

> 不要试图在 GitHub Actions 里跑 Postfix：Actions 的运行机没有固定公网 IP、不开放 25 端口、每次运行都是新机器，收信和直连发信在原理上就不可能。

---

## 二、操作步骤

### 1. 注册 Resend 并添加域名

1. 打开 [resend.com](https://resend.com) 注册（GitHub 账号可直接登录）
2. 左侧 **Domains → Add Domain**，填入你的域名（建议同时添加 `yourdomain.com` 和子域 `mail.yourdomain.com`，前者更简洁）
3. Resend 会列出需要添加的 DNS 记录，通常是这样 4 条：

| 类型 | 名称（Host） | 值 | 用途 |
|---|---|---|---|
| TXT | `@` 或 `resend._domainkey` | `p=MIGfMA0GCS...`（很长一串） | **DKIM** 签名，最重要的记录 |
| TXT | `@` 或 `send` | `v=spf1 include:amazonses.com ~all` | **SPF**，声明谁有权代你发信 |
| MX | `send`（若使用子域自动生成） | `feedback-smtp.us-east-1.amazonses.com` 优先级 10 | 接收退信 |
| TXT | `_dmarc` | `v=DMARC1; p=none;` | **DMARC** 策略，建议加上，显著提升送达率 |

> 以 Resend 控制台实际显示的为准，不同域名后缀和区域会略有差异。若你已有 SPF 记录，**不要新建**，而是把 `include:amazonses.com` 合并进已有那条。

### 2. 在 DNS 服务商添加记录

域名刚买、还没配 DNS 的话，先根据你买域名的平台操作：

- **域名在国内平台（阿里云/腾讯云/华为云）买的**：进入"域名解析"控制台 → 添加记录 → 按上表逐条填
- **域名在国外平台（Namecheap/Cloudflare/GoDaddy）**：建议把 NS 转到 Cloudflare 免费版，解析界面更清晰、改记录秒生效

添加时注意：

- 主机记录填 `@` 表示根域名，填 `send` 表示 `send.你的域名`
- 记录值**原样粘贴**，不要多加空格或引号
- TTL 用默认值即可

### 3. 回 Resend 点 Verify

记录添加后点 **Verify DNS Records**，通常 1～10 分钟通过（最长可能要几小时，取决于原 DNS 的缓存时间）。

验证通过后，发件人就可以用这个域名的任意地址，比如 `notice@你的域名`、`noreply@你的域名`。

### 4. 创建 API Key

Resend 左侧 **API Keys → Create API Key**，权限选 **Sending access**，域名选刚验证的那个。复制得到的 `re_xxxxxxxx`（**只显示一次**）。

### 5. 填写配置

**本地**：在仓库根目录的 `.env` 里填 `RESEND_API_KEY`、`MAIL_FROM_ADDRESS`、`MAIL_TO`。

**CI（GitHub Secrets）**：仓库 `Settings → Secrets and variables → Actions` 添加：

| Secret | 值 | 示例 |
|---|---|---|
| `RESEND_API_KEY` | 上一步的 `re_...` | `re_abc123...` |
| `MAIL_FROM_ADDRESS` | 纯发件地址（不带显示名） | `notice@yourdomain.com` |
| `MAIL_TO` | 收件地址（多个用英文逗号） | `you@qq.com` |
| `MAIL_FROM_NAME` | 可选，显示名 | `研电赛通知` |

**Cloudflare Worker**（它也用同一个域名发登录邮件与站长通知）：在
Dashboard → Settings → Variables and Secrets 里把 `RESEND_API_KEY` 填为 Secret，
`MAIL_FROM_ADDRESS` / `MAIL_FROM_NAME` 填为 Variable。完整清单见
[Cloudflare自动部署指南](Cloudflare自动部署指南.md) 第三节。

> `config.yaml` 已不再包含任何发信配置，无需改动；发信相关项全部走 `.env` / Secrets。
> 变量优先级：CI/Cloudflare 注入的环境变量 > `.env` > 内置默认值。

### 6. 测试

Actions 页面 → 选中「研电赛通知推送」→ **Run workflow**，输入框填 `normal` 运行。
日志里应看到：

```
发信通道：resend（研电赛通知 <notice@yourdomain.com>）
Resend 已投递 -> you@qq.com（id=...）
```

## 三、免费额度与限制

| 项 | Resend 免费版 |
|---|---|
| 每月邮件数 | 3,000 封 |
| 每天邮件数 | 100 封 |
| 发件域名 | 1 个 |
| 你的用量 | 每天 1 封，一个月约 30 封 — 远低于上限 |

`MAIL_TO` 可以填多个收件人，但仍算作多封。想发给一个班级/课题组时，把地址用逗号隔开即可。

## 四、常见问题

**Q：验证一直 pending？**
用 `dig TXT resend._domainkey.你的域名 +short` 检查记录是否已生效。DNS 缓存未过期是最常见原因，等 10 分钟再点 Verify。

**Q：邮件进了垃圾箱？**
1. 确认 `_dmarc` 那条 TXT 已加；
2. 若域名是新注册的，前几天会有"域名太新"的降权，正常现象；
3. 在收件箱把发件人加入白名单。

**Q：能收信吗？**
`notice@你的域名` 只是发件人身份，别人回复会进不了任何邮箱。想接回信：
用 [Cloudflare Email Routing](https://developers.cloudflare.com/email-routing/)（免费）加一条 MX → 转发到你的 QQ 邮箱，两步搞定。

**Q：Resend 挂了怎么办？**
把 `.env` 的 `MAIL_PROVIDER` 改成 `smtp`（CI 上改同名 Secret），再填 `SMTP_USER` / `SMTP_PASSWORD` 即可切回邮箱授权码模式，代码无需改动。

**Q：能用其他服务商吗？**
可以，修改 `yds/senders.py` 里 `ResendSender.ENDPOINT` 与请求体即可适配 Brevo / Mailgun / 阿里云邮件推送。国内收件多时，阿里云 DirectMail 的国内送达率会更好（需域名备案）。
