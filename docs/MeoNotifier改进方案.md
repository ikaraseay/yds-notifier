# MeoNotifier 改进方案

将「研电赛通知订阅器」升级为 **MeoNotifier**，一个以通知组为单位的公开网站更新订阅服务。获得创建权限的用户可把多个网址组织为一个通知组，为每个网址编辑监控提示词，并决定是否公开给其他用户订阅。研电赛作为首个内置通知组，保留报名、评审、决赛、截止日期和角色提醒等规则。

## 创建和订阅通知组

1. **管理员授权。** 普通用户默认只能订阅公开组和内置组。管理员在 `/admin` 按账号授予或收回「创建通知组」权限，服务端校验创建请求并记录授权时间和操作者。收回创建权限后，已有组仍归原组主。若需停止一个组的公开或投递，管理员可对该组单独处理。
2. **组主批量添加网址。** 在「我的通知组」新建一个默认私有的组，逐行粘贴一个或多个 URL。后台去重并逐条分析，展示每个地址的处理进度、失败原因和重试入口。某个地址失败时，其余成功结果仍可使用。
3. **逐条确认提示词。** Agent 根据站点规则、候选数据源和实际试抓样本，为每个能成功分析的 URL 生成一段可编辑的短提示词。以「校园资助」组为例，研究生院公告页可设置「只提醒奖学金申请及截止日期变更」，资助中心的 RSS 可设置「只提醒助学金和困难补助」。预览展示标题、来源、原文链接和匹配原因。组主确认后启用组内监控。
4. **按组投递。** 组内的每个 URL 独立检查和判断相关性。同一则更新在组内合并，按订阅者选择的即时、日报或周报频率发送。组主可暂停或编辑监控，订阅者可调整自己的频率或退订。首次成功抓取建立基线，后续才推送新增和实质变化。

## 公开审核

通知组默认私有，仅组主可见并接收。组主主动申请公开时，页面预览公开目录将展示的组名、说明、监控来源和公开者的**已验证邮箱**。组主确认邮箱将被其他登录用户看到后，才能提交审核。公开组的订阅者名单和试抓原始样本仍按账号隔离。

每次申请公开时，后台针对待发布版本检查组名、说明、全部 URL 和逐 URL 提示词。全部通过后发布到目录，其他已验证邮箱的用户可订阅。检查失败时保留私有状态，并反馈具体地址、提示词及失败原因。无法自动判定的项目进入管理员复核。

| 检查对象 | 公开条件 |
|---|---|
| URL | 地址可通过公开网络访问，实际请求和重定向符合出站限制与站点抓取规则。需要登录、含访问令牌或指向受限内容的链接退回。 |
| 提示词 | 任务范围限于分析该来源的公开更新。检测个人敏感信息、绕过访问限制、读取密钥、执行外部操作或收集私人数据等要求。 |
| 发布版本 | 审核绑定具体内容。公开后新增或修改 URL、提示词或公开说明时，新版本重新检查，审核期间按已发布的版本运行。审核期间再编辑时，旧审核结果仅适用于当时的版本。已发布来源因站点规则变化而不再允许抓取时，暂停该来源并通知组主。 |

首版建议公开目录仅对已登录用户可见，完整提示词和 Skill 调整记录由组主与审核管理员查看。组主撤回后停止新订阅和面向其他用户的后续发送，现有订阅显示该组已撤回。管理员可下架组并记录原因。公开目录与现有通知归档使用独立入口。

## Agent 如何分析和抓取

| 步骤 | 系统行为 |
|---|---|
| 检查网址与站点规则 | 校验公开 HTTP(S) 地址和每一跳重定向。读取目标 origin 的 `robots.txt`，按 MeoNotifier 的爬虫标识和目标路径判断能否请求。匹配禁止规则时暂停该路径。网络异常、5xx、限流或访问受限时暂停试抓或退避重试。 |
| 发现数据源 | 优先使用站点提供的 RSS、Atom 或公开 API。用站点地图、`llms.txt` 和首页同源链接发现候选栏目。对于普通 HTML，支持监控一个正文区域，或从一个列表页提取条目。 |
| 生成可复用的抓取配置 | Agent 分析少量样本，为每个 URL 建议监控范围、提取方式、忽略区域和一段短提示词。程序校验配置并实际试抓，由组主修改或确认。页面改版、访问受限或连续失败时，显示最后成功时间和失败原因。 |
| 识别变更并投递 | 使用规范化 URL、源条目 ID 和正文指纹识别新增及更新，过滤导航、广告和动态时间戳。发现实质变化后，按订阅规则判断相关性，生成带原文链接的摘要。模型调用失败时可以发送基于原文的简短变更通知。 |

`robots.txt` 的规则匹配和异常处理参考 RFC 9309。当前项目在获取失败时会放行，自定义抓取上线前应区分文件确实缺失和暂时不可达。遇到 404 或 410 时可继续发现入口，并在结果中标明规则文件缺失。`llms.txt` 提供站点说明、推荐链接和 Markdown 入口，每个候选地址仍需检查访问限制和站点条款。研电赛预设中的来源同样按这套规则逐个检查。项目 README 记载研创网曾明确限制抓取，预设上线时需要重新核验并确认可用来源。 [RFC 9309](https://datatracker.ietf.org/doc/html/rfc9309#section-2.3.1)、[llms.txt 提案](https://llmstxt.org/)、[现有数据源说明](../README.md#disclaimer)

用户输入、重定向、RSS 条目和站点索引都可能指向本机、内网或云元数据地址。试抓与定时抓取使用同一套 URL 校验和出站限制，对实际连接地址执行校验，并限制请求频率、并发、响应大小和发现范围。网页和 `llms.txt` 内容作为待分析的数据传给模型。模型只返回通过校验的抓取建议、分类和摘要，抓取范围和收件人由程序控制。

## 公开组的 Skill 与迭代

每个通知组首次通过公开审核时，生成一个独立的 **Skill v1**，由 MeoNotifier 在运行时加载。Skill 保存经审核的来源范围、组主确认的逐 URL 提示词、提取配置、去重规则和摘要格式。组主确认的提示词作为订阅意图的基线，演化记录单独保存，方便查看和回滚。

1. **每次通知后评估。** 同一个组的同一批变更只评估一次。Agent 根据本轮原文、实际变更、匹配原因、历史重复记录，以及有数据时的用户反馈，生成有证据的候选调整。邮件投递状态只用于判断送达，内容质量由样本和反馈评估。候选调整可包括忽略站点页脚、收紧重复判断或改进摘要格式。
2. **发布前验证。** 用当前和历史样本同时运行旧版本与候选版本，比较误报、漏报、原文链接和关键信息准确性。首版展示差异，由组主确认后发布。后续可允许效果可验证的低风险调整自动生效，并保留评估和版本记录。每次通知都会触发评估，有有效改进时才生成新版本。
3. **控制变更范围。** Skill 可以优化提取和呈现。增加 URL、扩大抓取范围或改变组主设定的监控意图，须由组主确认并走公开审核。抓取限制、可见性、权限和收件人由服务端控制。出现异常可恢复到上一版本。通知组暂停公开时，停用公开 Skill 及其迭代任务。

## 数据、运行和推送

保留 Cloudflare Worker 的邮箱登录和管理后台，增加「我的通知组」、公开目录及管理端的创建授权、审核和下架入口。Worker 将批量试抓、公开审核和 Skill 评估记为任务，Python 通过受保护的接口读取任务并回传结果。试抓可由按需运行处理，定时监控首版沿用现有 GitHub Actions 调度。控制台显示预计检查频率。「即时」指这一轮发现后发送，发送时间仍受抓取周期约束。

系统分别记录通知组及其草稿和已发布版本、组内来源及逐 URL 提示词、公开审核、Skill 版本、用户订阅和投递。来源可以在相同抓取配置下复用抓取结果，各组按自己的提示词判断是否发送。投递按订阅和变更版本记录待发、成功和失败，重试沿用同一投递标识。发信前重新检查组和订阅是否仍启用，避免撤回或退订后发送已排队的邮件。用户可在个人控制台查看自己的订阅和投递状态。

通用更新保留标题、来源、原文、发布时间和变更摘要。研电赛作为系统维护的内置通知组，通过 `python -m backend --skill yds` 独立运行。其来源、赛程提醒、赛事契约、角色规则及版本化提示词位于 [skills/yds](../skills/yds)。普通用户可一键订阅此预设。若后续要让外部 Agent 创建和管理通知组，再提供独立的集成入口。

## 品牌和迁移

先统一用户可见的品牌。站点标题、发件人显示名、邮件主题前缀、正文与页脚、登录和退订邮件、RSS 说明及推送标题统一使用 **MeoNotifier**。赛事邮件可以使用「[MeoNotifier] 研电赛｜报名截止日期更新」这样的主题，让用户一眼看到产品名和订阅来源。发件地址沿用已验证域名，研电赛预设继续保留原文链接和非官方说明。

GitHub 仓库可以在品牌切换后单独改名。改名之前清点 Cloudflare Workers Builds、GitHub Actions、部署脚本、仓库链接、GitHub Pages 和外部集成，再验证 CI 与自动部署。GitHub 为大多数旧仓库链接提供重定向，项目网站 URL 和其他工作流引用的 GitHub Action 需要单独处理。域名、Worker 名称、存储和旧邮件中的签名链接可在品牌切换期间继续使用。 [GitHub 仓库改名文档](https://docs.github.com/en/repositories/creating-and-managing-repositories/renaming-a-repository)

## 实施顺序和验收

1. **跑通私有通知组。** 验证普通用户创建请求被拒、授权后可创建私有组、批量添加中单个 URL 失败可重试、提示词可逐条编辑、首次建立基线后收到实际变更邮件，以及其他账号无法读取或修改私有组。
2. **开放审核和订阅。** 验证违规或受限 URL 无法随组公开，修改后触发重审。审核通过的组展示公开者已验证邮箱并可订阅。验证撤回、下架和退订后的待发任务，以及公开前后账号数据的访问范围。
3. **上线公开组 Skill，迁移研电赛并完成品牌切换。** 验证每次通知触发评估、候选版本可用历史样本验证、扩大范围须重新审核、旧版本可恢复。迁移存量赛事订阅和去重状态，验证邮件、退订、个人日历与归档。
4. **根据失败样本扩大覆盖范围。** 收集试抓失败和误报案例，再评估动态网页渲染、专用适配器、Webhook 或其他推送渠道。仓库和基础设施标识按迁移清单逐项处理。

- **Horizon** 的来源配置和处理 Profile 可以独立演进，内容经过筛选、去重、分析，再进入简报。MeoNotifier 可用同样的边界组织通用摘要和研电赛预设。 [Thysrael/Horizon](https://github.com/Thysrael/Horizon#how-it-works)
- **changedetection.io** 支持按 CSS 选择器或 XPath 聚焦局部内容、过滤噪声，并在变化时通知。它可以作为网页监控配置和通知触发的参考。 [changedetection.io](https://github.com/dgtlmoon/changedetection.io#filters)
- **Harvest** 尚未定位到唯一的目标仓库。待确认链接后，再评估其站点发现、提取配置和调度机制是否适合复用。
