# 简易版单页通知站 · Agent 提示词

> 用途：把下面的提示词整体复制给一个 AI 编程 Agent（如 Claude Code、Cursor、WorkBuddy 等），即可产出「研电赛通知 · 简易版」单页站点。提示词已内置原项目的视觉规范与数据结构，无需额外上下文。

---

## 提示词正文（从这里开始复制）

你是一位资深前端工程师。请为我制作「研电赛通知 · 简易版」——一个**只有一个网页**的轻量站点，直接展示从官方渠道获取到的竞赛信息与通知。整体风格延续原项目（研电赛通知订阅器）的孟菲斯设计语言，**简约大气，全程不使用 emoji**。

### 一、目标与范围

- 产出单个 `index.html` 文件：HTML + CSS + JS 全部内联，不引用任何外部资源（无 CDN、无字体文件、无图片请求），双击即可打开。
- 页面定位：一屏看清「最近有哪些通知、哪个重要、什么时候截止」，点标题跳转官方原文。
- 不需要：登录、订阅、退订、控制台、RSS、日历订阅等原项目的复杂功能。

### 二、数据获取（关键约束）

浏览器直接跨域抓取 `cpipc.acge.org.cn`、`www.cie.org.cn` 会被 CORS 拦截，因此二选一（推荐 A）：

- **方案 A（推荐）**：页面加载后 `fetch` 同目录的 `notices.json`。我会在部署时用现有系统的 `/feed.xml`（RSS）或 `/api/notices` 定期导出这份 JSON；请同时给我一段能跑在 GitHub Actions 里的最小拉取脚本（Python，把 RSS 解析成 notices.json 并提交回仓库），脚本放在提示里说明即可，不用建仓库结构。
- **方案 B**：页面直接 `fetch` 一个可配置的 JSON/RSS 地址（写在 HTML 顶部一个常量里），支持跨域时自动生效，失败时展示内置的 8–10 条示例数据并显示「数据源不可用」提示。

无论哪种方案：**页面必须内置一份示例数据**（10 条左右，覆盖不同分组与紧急度），保证离线打开也是完整可演示的效果。

### 三、数据结构（与原系统一致，字段均为可选）

```json
{
  "notices": [
    {
      "uid": "cpipc:6:1234",
      "title": "关于举办第二十届中国研究生电子设计竞赛的通知",
      "url": "https://cpipc.acge.org.cn/cw/hp/4c908a...",
      "date": "2026-03-10",
      "category": "大赛通知",
      "source": "研创网",
      "summary": "原摘要文本……",
      "aiCategory": "报名参赛 | 评审与名单 | 决赛与收官 | 赛事动态 | 其他通知",
      "aiSummary": "一句话摘要",
      "aiUrgency": "critical | high | normal | low",
      "stage": "报名 | 资格审查 | 缴费 | 提交作品 | 评审 | 决赛 | 公示 | 获奖 | 报销 | 承办 | 动态 | 其他",
      "audiences": ["student", "advisor", "admin", "organizer"],
      "action": "在截止日前完成报名信息填写",
      "aiEvents": [
        { "date": "2026-04-30", "label": "报名截止", "kind": "deadline", "location": "" }
      ],
      "changeKind": "new | changed",
      "contest": "电子设计竞赛"
    }
  ],
  "generatedAt": "2026-11-06T03:34:00Z"
}
```

人群标签映射：student=参赛学生、advisor=指导教师、admin=培养单位、organizer=分赛区/承办方。

### 四、页面结构与交互

1. **头部**：大标题「研电赛通知」（标题中「通知」二字用珊瑚色高亮块包裹），副标题一句：「中国研究生电子设计竞赛 · 官方通知一站式速览」。右上角一个小圆标记（黄底黑描边）。
2. **统计条**：显示「共 N 条 · 最近更新 YYYY-MM-DD HH:MM」。
3. **筛选栏**：按分组（全部 / 报名参赛 / 评审与名单 / 决赛与收官 / 赛事动态）的胶囊按钮；旁边一个「只看重要」开关。筛选纯前端完成。
4. **通知列表**：按日期倒序的卡片流，每张卡片包含——
   - 元信息行：日期 · 阶段 · 来源；
   - 标题（可点击，`target="_blank" rel="noopener noreferrer"`）；
   - 一句话摘要（aiSummary，无则用 summary，超过两行省略）；
   - 关键日程：aiEvents 逐条列出「标签：日期」，deadline 类型的日期用珊瑚色加粗；
   - 行动建议：action 存在时显示「要做什么：…」；
   - 面向人群：有值时显示标签组；
   - 徽标：`aiUrgency === "critical"` 显示「重要」（珊瑚底白字），`changeKind === "changed"` 显示「更新」（黄底黑字）。
5. **空态**：「暂时还没有收录通知，过段时间再来看看吧。」
6. **页脚**：一行小字「数据来自研创网与中国电子学会官网，请以官方原文为准 · 本页每天自动更新」。

### 五、视觉规范（孟菲斯主题，必须严格执行）

设计令牌：

```css
--bg: #FFF4E4;        /* 奶油纸底 */
--ink: #2E2A33;       /* 墨色，所有描边与正文 */
--coral: #FF6B6B;     /* 珊瑚：重要徽标、标题高亮 */
--yellow: #FFD93D;    /* 黄：主按钮、标记、选中态 */
--blue: #4D96FF;      /* 蓝：链接、聚焦态 */
```

硬性规则：

- 页面背景：`#FFF4E4` + 波点纹理 `radial-gradient(#2E2A33 1.5px, transparent 1.5px)`，`background-size: 22px 22px`。
- 卡片：白底、`border: 3px solid var(--ink)`、`border-radius: 8px`、**硬阴影** `box-shadow: 8px 8px 0 var(--ink)`（小元素用 4px）。绝不用模糊阴影、渐变按钮或大圆角。
- 列表容器：白色大卡片，`max-width: 680px` 居中；内部条目用 `border: 2px dashed` 或细实线分隔，行内元信息用 `#6b6572` 小字。
- 字体栈：`-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`；正文 14px / 行高 1.75，标题 800 字重。
- 链接：蓝色、粗体、`text-underline-offset: 3px`。
- 入场动画：卡片 `translate(8px,8px)+阴影收拢` 到位，`cubic-bezier(.22,.9,.28,1)` 200ms；筛选切换时条目重新入场。
- 筛选按钮：黑描边胶囊，选中态黄底 + 4px 硬阴影；`:active` 时 `translate(4px,4px)` 且阴影归零（按压手感）。
- `@media (prefers-reduced-motion: reduce)` 下关闭全部动画与过渡。
- 移动端（≤420px）：内边距、阴影、字号整体缩一档，单列布局不变。
- 全程无 emoji、无图标库、无外部图片；装饰一律用 CSS（圆点、色块、描边）实现。

### 六、质量要求

- 所有从 JSON 注入的内容必须 HTML 转义（先转义再插 DOM，或使用 `textContent`），杜绝 XSS。
- URL 只接受 `http/https` 绝对地址，其余丢弃。
- 加载数据失败时降级到内置示例并明确提示，不白屏。
- 不依赖任何框架与构建工具；`tsc`/lint 不适用，但代码需通过浏览器直接打开自检。
- 语义化标签 + 基本无障碍：按钮真实 `<button>`，链接可键盘聚焦，焦点态用蓝色 `outline: 3px solid` + `offset: 3px`。

### 七、验收标准（完成后自检）

1. 断网双击打开 `index.html`：完整渲染示例数据，无控制台报错。
2. 替换 `notices.json` 后刷新：列表、筛选、「只看重要」全部正确联动。
3. 含 `critical` 徽标、`changed` 徽标、多事件日程、无 aiEvents 的条目各至少一条且样式正确。
4. 视觉与上述令牌逐项一致：波点背景、粗描边、硬阴影、无 emoji、无模糊阴影。
5. 375px 宽度下无横向滚动条。

先给出实现方案的一句话确认（数据走方案 A 还是 B），再直接产出完整 `index.html`（以及方案 A 对应的拉取脚本），不要输出多余解释。
