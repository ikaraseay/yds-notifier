# 订阅页面部署指南（Cloudflare Worker）

Worker 是一个**带账号的订阅中心**：打开链接、填邮箱、点邮件里的登录链接，就直接进入控制台——无需注册表单，也无需设置密码。首次登录自动建档并开始订阅，之后可勾选想收的栏目，或一键注销账户。

**部署已改为 Cloudflare 连接 GitHub 自动构建**，完整步骤与环境变量清单见 **[Cloudflare自动部署指南](Cloudflare自动部署指南.md)**。本文只讲账号模型、界面/逻辑分层与接口。

```
访客填邮箱 → Worker 校验+限流 → 发登录链接 → 访客点链接
                                                  ↓
                校验 nonce → 首次则建档+订阅 → 写会话 cookie → 302 控制台
                                                  ↓
                控制台：勾选栏目（即时保存） / 退出登录 / 注销账户
                                                  ↓
GitHub Actions 每轮推送前 → GET /api/list（含各人 prefs） → 按栏目过滤后逐个发信
```

---

## 一、代码分层

源码在 `worker/src/`，界面与后端信息逻辑分离，构建时由 esbuild 合并成 `dist/index.js`：

| 目录 | 职责 |
|---|---|
| `ui/styles.ts` | 页面样式（孟菲斯卡片风格） |
| `ui/scripts.ts` | 前端 JS（登录表单提交、控制台勾选即存） |
| `ui/layout.ts` | HTML 骨架、一次性 CSP nonce、统一安全响应头 |
| `ui/pages.ts` | 登录页 / 控制台 / 通用结果页 |
| `handlers/login.ts` | 魔法链接登录、首次建档订阅 |
| `handlers/dashboard.ts` | 偏好保存、退出、注销 |
| `handlers/unsubscribe.ts` | 按邮箱退订 |
| `handlers/api.ts` | 订阅名单、人数、健康检查 |
| `env.ts` / `security.ts` / `rate.ts` / `mailer.ts` / `auth.ts` | 配置、安全原语、限流、发信、账号模型 |
| `index.ts` | 只做 method 白名单 + 路由分发 + 统一错误处理 |

所有页面响应都带 `Content-Security-Policy`，脚本与样式用**每次响应随机生成的 nonce** 授权，不再使用 `unsafe-inline`。

## 二、首次部署要点

1. 创建 KV，把 id 填进根目录 `.env` 的 `KV_SUBS_ID`，跑 `npm run sync-config` 同步进 `wrangler.toml`
2. 在 `.env` 填 `CUSTOM_DOMAIN`（自定义域名）或 `WORKERS_DEV_URL`；`sync-config` 会自动生成 `[[routes]] custom_domain = true`
3. Cloudflare → Settings → Builds 连接 GitHub，Root directory 填 `worker`，Build command 填 `npm ci && npm run sync-config && npm run build`，Build variables 填 `KV_SUBS_ID` 与 `CUSTOM_DOMAIN`
4. 在 **Variables and Secrets** 填：
   - Secrets：`UNSUB_SECRET`、`RESEND_API_KEY`、`SUBSCRIBE_API_TOKEN`
   - Variables：`CUSTOM_DOMAIN`（或 `WORKERS_DEV_URL`）、`MAIL_FROM_ADDRESS`（必填）、`MAIL_TO`、`SITE_NAME`、`MAIL_FROM_NAME`、限流参数
5. GitHub Actions Secrets 填 `CUSTOM_DOMAIN` / `SUBSCRIBE_API_TOKEN` / `UNSUB_SECRET` 等同名同值项

**三处一致性**：`UNSUB_SECRET` 两边相同；`SUBSCRIBE_API_TOKEN` 两边同名同值；`CUSTOM_DOMAIN` 两边同值（`UNSUB_URL` / `SUBSCRIBE_API_URL` 由它派生，不用再填）。详细表格见自动部署指南第三、四节。

> Worker 已**不再需要** `GITHUB_TOKEN` / `GITHUB_OWNER` / `GITHUB_REPO` / `WORKFLOW_FILE` / `ADMIN_TOKEN`，也不再持有任何 GitHub 凭据。旧变量名仍被代码兼容。

## 三、账号模型

### 魔法链接登录（无密码）

| 环节 | 实现 |
|---|---|
| 发链接 | `POST /api/login` → 生成 48 位随机 nonce，KV 存 `magic:<sha256(nonce)>`，TTL 900 秒 |
| 点链接 | `GET /login?n=<nonce>` → 取出记录并**立即删除** → 建 user、进订阅名单、写会话 |
| 一次性 | 删除发生在校验之前，同链接第二次访问必然失败 |
| 会话 | cookie `yds_sid` 存 64 位随机串；KV 只存 `session:<sha256>`，泄库无法回推 cookie |
| 有效期 | 14 天，`HttpOnly; Secure; SameSite=Lax` |
| 链接域名 | 由 `PUBLIC_BASE_URL` → `https://<CUSTOM_DOMAIN>` → `<WORKERS_DEV_URL>` 派生，**不信任请求 Host**，防 Host 头注入钓鱼 |

不用密码的好处：没有密码可以泄露、可以撞库、可以忘记；用户也没有「注册」的心理成本。

### 四个栏目

| key | 名称 | 默认 | 包含内容 |
|---|---|---|---|
| `registration` | 报名参赛 | 开 | 报名通知、赛事章程、赛题指南 |
| `review` | 评审与名单 | 开 | 初赛评审、晋级公示、获奖名单（「其他通知」也归这里） |
| `final` | 决赛与收官 | 开 | 总决赛安排、证书、发票报销 |
| `updates` | 赛事动态 | **关** | 分赛区新闻、倒计时、赛事花絮 |

栏目与 `yds/models.py` 的 `Notice.category` 通过 `worker/src/auth.ts` 与 Python 端 `yds/recipients.py` 的 `CATEGORY_TO_KEY` 双向对齐。**改栏目时两边都要改**，否则映射不到的分类会漏发（宁可漏不可误）。

### 注销

`POST /api/delete-account` 依次删除 `user:<email>`、`sub:<email>`，**清理该邮箱的全部设备会话**，并把 `meta:count` 减一，等同于从未注册。注意「退订」和「注销」是两件事：

- **退订**（邮件底部链接）→ 只删 `sub:`，账号与栏目设置保留，重新登录控制台即可恢复
- **注销**（控制台按钮）→ 账号、订阅、偏好、全部会话都删除，不可恢复

## 四、防滥用设计

| 层 | 机制 | 防什么 |
|---|---|---|
| 1 | **IP 限流**：每 IP 每小时 3 次提交 | 单人刷登录信 |
| 2 | **邮箱冷却**：同邮箱 10 分钟 1 封 | 拿别人的邮箱当轰炸目标 |
| 3 | **全局熔断**：每天最多 200 封 | 批量脚本刷爆 Resend 额度 |
| 4 | **一次性签名链接**：nonce 随机 + 15 分钟过期 + 用过即删 | 链接被转发、被日志留存后重放 |

另外：

- **CSRF**：所有状态变更 POST 校验 `Origin` / `Sec-Fetch-Site`，跨站请求返回 403
- **method 白名单**：每个路由只接受自己的 HTTP 方法，其余 405 + `Allow` 头
- **错误不回显**：上游 Resend / 内部异常细节只写 `console.error`，页面只显示通用文案
- **CSP nonce**：脚本与样式按响应随机 nonce 授权，禁外部脚本、禁框架嵌入
- **签名 token**：退订链接绑定邮箱 + 过期时间，HMAC-SHA256，改一个字符都无效
- **GET/POST 分离**：退订页 GET 只展示，POST 才执行，防邮件客户端预抓链接误退订
- **输入过滤**：邮箱格式校验 + 测试域名拒绝 + 长度限制 + 偏好字段白名单

### 限流为什么用 Durable Object 而不是 KV

KV 免费版**每天只有 1,000 次写入**、同一 key 每秒仅 1 次写。限流计数器每次请求都要写，攻击者几分钟就能打爆配额，且 KV 无原子累加。Durable Object 的存储是原子的，免费版每天 10 万次请求，计数场景绰绰有余。这也是 `wrangler.toml` 里必须声明 `new_sqlite_classes` 的原因（免费版只支持 SQLite 后端的 DO）。

KV 写入配额留给账号本身：一次登录约 3 次写、一次注销约 4 次写，日活几十人完全够用。

## 五、隐私设计

- **逐个发信**：每个订阅者单独收到一封邮件，互相看不到对方地址
- **退订链接一人一签**：链接带该订阅者邮箱的独立签名，只能退订自己
- **站长只收通知**：有人新订阅 / 退订 / 注销时你会收到一封通知邮件
- **注销即彻底删除**：不留软删除标记，KV 里查不到任何痕迹

## 六、管理订阅名单

```bash
cd worker
npx wrangler kv key list --binding SUBS --prefix "user:"
npx wrangler kv key get "user:someone@qq.com" --binding SUBS

# 手动移除某人（user: 与 sub: 都要删才算彻底）
npx wrangler kv key delete "sub:someone@qq.com" --binding SUBS
npx wrangler kv key delete "user:someone@qq.com" --binding SUBS

# 修正订阅人数显示
npx wrangler kv key put "meta:count" "42" --binding SUBS
```

## 七、接口一览

| 路由 | 方法 | 说明 |
|---|---|---|
| `/` | GET | 已登录→控制台；未登录→登录页 |
| `/api/login` | POST | 提交邮箱，发登录链接（限流后） |
| `/login?n=` | GET | 点链接：校验→注册→写会话→302 到控制台 |
| `/dashboard` | GET | 控制台（需会话） |
| `/api/prefs` | POST | 保存栏目偏好（需会话 + 同源） |
| `/api/logout` | POST | 退出登录（保留账号与订阅） |
| `/api/delete-account` | POST | 注销（删除账号、订阅、偏好、全部会话） |
| `/unsubscribe?email=&token=` | GET / POST | 退订（GET 确认页，POST 执行，含 RFC 8058 One-Click） |
| `/api/list` | GET | 拉名单 + 偏好（需 `Authorization: Bearer <SUBSCRIBE_API_TOKEN>`，带限流） |
| `/api/count` | GET | 订阅人数 |
| `/health` | GET | 健康检查 |

`/api/list` 响应兼容新旧两种结构：

```json
{
  "ok": true,
  "count": 2,
  "emails": ["alice@qq.com", "bob@qq.com"],
  "subscribers": [
    { "email": "alice@qq.com", "prefs": { "registration": true, "review": false, "final": true, "updates": false } },
    { "email": "bob@qq.com", "prefs": { "registration": true, "review": true, "final": true, "updates": true } }
  ]
}
```

## 九、常见问题

**订阅者会收到别人的邮箱地址吗？**
不会。逐个发信，每封邮件 To 只有收件人自己；控制台也只能看到自己的地址。

**有人刷登录怎么办？**
三层限流（IP / 邮箱 / 全局）。没点开链接的人不会建档，也不会占用正式通知的发送额度。

**忘记上次选了什么栏目？**
偏好在服务端，重新登录就是上次离开时的状态。

**能不能只订阅一个栏目？**
可以，四个栏目互相独立，全关也能保存（等于暂不收信但保留账号）。彻底停止请用控制台的注销。

**误点了注销怎么办？**
无法恢复，需要重新登录一次，新账号使用默认偏好。
