## 二、严重问题

### S-01 退订链接 100% 校验失败（功能性 + 合规风险）

**位置**：`backend/unsub.py:32-46`、`cloudflare/src/index.ts:138-146`

Python 端 `make_email_token()` 默认 `expire_ts=0`，生成 `"0.<sig>"`，注释写明「exp 用 0 表示长期有效」。但 Worker 端 `verifySubToken()` 的过期判断是：

```ts
const ts = Number(exp);
if (!Number.isFinite(ts) || ts * 1000 < Date.now()) return false;
```

`0 * 1000 = 0 < Date.now()` 恒成立，因此**所有按邮箱签发的退订链接都被判定为过期**。旧版 `verifyLegacy()` 反而对 `"0"` 做了特判放行。最终表现是：邮件正文的「一键退订」和 `List-Unsubscribe` / `List-Unsubscribe-Post`（RFC 8058 一键退订）全部返回 400，用户无法退订，唯一"能用"的却是会停掉整个定时任务的旧链接。

这既是缺陷也是合规风险（批量邮件必须提供有效退订渠道，Gmail/Yahoo 自 2024 起对一键退订有强制要求，退订失效会直接影响送达率）。

**修复**：双方统一为「带过期时间的 token」：Python 签发 `exp = now + UNSUB_TTL_DAYS`（默认 180 天），Worker 校验 `now <= exp <= now + 最大窗口`，并显式拒绝 `exp <= 0`。新增 Python 侧签名一致性自测，避免再次漂移。

### S-02 全局退订 = 单人可令全部订阅者停收（DoS）+ 长期 PAT

**位置**：`cloudflare/src/index.ts:94-102, 257-269, 885-922`、`cloudflare/wrangler.toml:41-45`

旧版兼容分支用 `GITHUB_TOKEN` 调 GitHub API **停用 `notify.yml` workflow**。任何拿到该链接的人（邮件被转发、邮件客户端预抓取、代理日志、浏览器同步）都能一次性让所有订阅者停止收信；且 token `exp=0` 永不过期，无法撤销单个链接。为了这个功能，Worker 里还长期保存着一个具备 `Actions: read/write` 的 fine-grained PAT，一旦 Worker 配置泄露，影响面从"一个订阅者"扩大到"整个仓库的 Actions"。

新版架构已有按邮箱的订阅名单，全局停用 workflow 在语义上也不再成立（一个人退订不应影响他人）。

**修复**：**彻底移除** legacy 分支、`setWorkflowState()` / `gh()` GitHub API 调用，以及 `GITHUB_TOKEN`、`GITHUB_OWNER`、`GITHUB_REPO`、`WORKFLOW_FILE` 四项配置。退订只删 `sub:<email>`。Cloudflare 少一个高权限密钥，攻击面显著缩小。

### S-03 登录链接域名取自请求 Host，可导致账号接管

**位置**：`cloudflare/src/index.ts:717-718`

```ts
const origin = new URL(req.url).origin;
const loginUrl = `${origin}/login?n=${nonce}`;
```

登录链接里的 `n` 是 48 位一次性 nonce，谁先拿到谁就能以该邮箱登录。若 Worker 绑定了自定义域、或在反代/回源配置下 Host 可被影响，攻击者可构造指向自己域名的请求，让受害者收到一封「看似官方、实则把 nonce 送给攻击者」的登录邮件。邮件正文同样会暴露这个恶意域名。

**修复**：新增固定的对外地址配置链 `PUBLIC_BASE_URL` → `https://<CUSTOM_DOMAIN>` → `<WORKERS_DEV_URL>`，所有对外链接（登录链接、通知邮件里的订阅页地址）一律由它派生，不再信任请求 Host；三者皆缺失时登录接口直接返回配置错误（fail-closed）。支持 Cloudflare 自定义域名后，`CUSTOM_DOMAIN` 与 `WORKERS_DEV_URL` 会同时进入 CSRF 的 Origin 白名单，两个入口都可用，其余来源一律 403。

## 四、中危问题与处置

| 编号 | 问题 | 处置 |
|---|---|---|
| S-09 | CSP 使用 `'script-src unsafe-inline'; 'style-src unsafe-inline'`，一旦出现注入点没有二次防线 | 每次响应生成 `crypto.randomUUID()` nonce，CSP 改为 `'nonce-xxx'` 源，内联脚本/样式带 nonce 才能执行 |
| S-10 | `/api/list` 无限流、无审计，暴露全部订阅者邮箱与偏好；`SUBSCRIBE_API_TOKEN` 可在线反复试 | 接入既有 Durable Object 限流（按 IP，60 次/小时），记录审计日志，只返回 Actions 必需字段 |
| S-11 | `safeEqual()` 用 HMAC 后 `===` 比较哈希字符串，非严格常量时间，且未限制输入长度 | 改为定长 XOR 累加比较，先做长度检查，超长输入直接拒绝 |
| S-12 | Python `recipients._valid()` 只检查 `@`、`.`、空格，未拒绝 CR/LF；SMTP 模式下收件人被 `", ".join()` 拼进 `To:` 头，存在邮件头注入 | 收紧为严格正则 + 控制字符拒绝，两端邮箱规则对齐 |
| S-13 | 抓取到的原文/附件 URL 未校验 scheme 与 host，可能把 `javascript:` 写进邮件 HTML；详情页 URL 直接 `urljoin` 后请求，存在 SSRF 面 | 渲染层只允许 `http/https`；抓取层校验目标 host 属于该数据源白名单 |
| S-14 | 注销账户只删当前会话，其它设备的 `session:` 记录残留到 14 天 TTL（因 `getUser` 失败暂不可利用） | 新增 `auth.ts::destroyAllSessions()`，注销时遍历 `session:` 前缀清理该邮箱全部会话 |
| S-15 | 邮箱枚举 / 登录反馈差异 | 已确认：响应文案对已注册与未注册一致，仅邮件正文不同，不构成枚举。保留现状 |

## 五、低危与运营建议（第 4、5 项已顺带修复）

1. **依赖供应链**：`requirements.txt` 与 `package.json` 都是范围版本，无 lockfile hash 校验。建议启用 Dependabot / Renovate，`pip-audit` + `npm audit` 纳入 CI。
2. **计数漂移**：`meta:count` 是读-改-写，并发注册时可能不准，仅影响页面展示，可接受；若需精确可改为 KV list 实时统计。
3. **配额型骚扰**：登录邮件即使发送失败也会消耗限流计数。已有 IP/邮箱/全局三层限流，风险可接受。
4. **Actions 权限（已修复）**：`notify.yml` 顶层改为 `permissions: {}`，仅在 `notify` job 授予 `contents: write`；新增的 `worker-ci.yml` 同样不授予任何权限。
5. **密钥轮换（已实现）**：新增可选 Secret `UNSUB_SECRET_PREVIOUS`，`security.ts::verifyUnsubToken()` 会依次用新旧密钥验签。轮换时先填旧密钥再更新新密钥，过渡期结束清空旧密钥即可，历史邮件里的退订链接不会突然失效。

## 六、修复后的安全边界

- **对外链接**：只由配置派生的固定地址生成（`CUSTOM_DOMAIN` / `WORKERS_DEV_URL` / 显式 `PUBLIC_BASE_URL`），Host 头不再被信任；支持自定义域名与 workers.dev 双入口
- **退订**：仅作用于单个邮箱，HMAC-SHA256 签名 + 180 天有效 + GET 确认 / POST 执行 + 严格 method 白名单
- **鉴权**：Cookie 会话（`HttpOnly; Secure; SameSite=Lax`）+ Origin/Sec-Fetch-Site 校验；`/api/list` 独立 Bearer Token + 限流
- **密钥**：全部在 `.env`（本地）/ Cloudflare Secrets（生产）/ GitHub Secrets（CI），仓库内只有 `.env.example` 与 `.dev.vars.example` 模板
- **响应**：统一安全头、CSP nonce、错误不回显内部细节
- **最小权限**：Worker 不再持有任何 GitHub 凭据

## 七、上线前必须人工确认

1. `UNSUB_SECRET` 与 `SUBSCRIBE_API_TOKEN` 使用 `openssl rand -hex 32` 重新生成，**不要沿用模板里的示例值**
2. Cloudflare 与 GitHub 两侧：`UNSUB_SECRET`、`SUBSCRIBE_API_TOKEN`、`CUSTOM_DOMAIN` 均**同名同值**（旧名 `ADMIN_TOKEN` 仅作兼容）
3. `CUSTOM_DOMAIN` 对应的 zone 已接入 Cloudflare；`UNSUB_URL` / `SUBSCRIBE_API_URL` 由它派生无需手填；若使用显式 `PUBLIC_BASE_URL`，须与 Cloudflare 的对外地址一致
4. Resend 域名已完成 DKIM/SPF/DMARC 验证，`MAIL_FROM_ADDRESS` 属于已验证域名
5. 若仓库曾经提交过任何真实密钥，视为已泄露，立即在对应平台轮换（本仓库当前未初始化 git，无历史提交，风险较低）
