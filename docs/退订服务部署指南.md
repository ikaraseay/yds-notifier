# 退订服务部署与签名契约

邮件底部的「一键退订」由 Cloudflare Worker 提供。它只做一件事：**校验链接签名，然后把这一个邮箱从订阅名单里移除**。账号与栏目偏好保留，重新登录控制台即可恢复订阅。

> **重要变更**：旧版「不带 email 的全局退订」会调用 GitHub API 停用 `notify.yml`，导致一个人点退订、所有订阅者都收不到信。该逻辑已删除，Worker 不再持有任何 GitHub 凭据。详见 [安全评审报告](安全评审报告.md) S-02。

---

## 一、为什么退订需要一个 Worker

| 平台 | 能收请求吗 | 说明 |
|---|---|---|
| GitHub Pages | 否 | 纯静态，只能展示页面 |
| GitHub Actions | 否 | 只跑定时任务，无法对外提供 URL |
| Resend | 否 | 只发信，不托管页面 |
| **Cloudflare Workers** | 是 | 免费额度足够，且可由 GitHub 自动部署 |

部署方式见 **[Cloudflare自动部署指南](Cloudflare自动部署指南.md)**：连接 GitHub 后 push 即自动构建部署，无需手动 `wrangler deploy`。

## 二、退订流程

```
Python 发信时按收件人邮箱签发链接
   → 邮件正文按钮 + List-Unsubscribe / List-Unsubscribe-Post 头（RFC 8058）
   → 收件人点击（或 Gmail 顶部「退订」直接 POST）
   → Worker 校验 HMAC + 过期时间 + 邮箱绑定
   → GET 显示确认页 / POST 删除 sub:<邮箱>
   → 订阅人数减一，站长收到一封通知
```

**两段式确认**：GET 只展示确认页，POST 才执行，防止邮件客户端预抓取链接导致「还没点就退订了」。RFC 8058 的 One-Click 由邮件客户端直接 POST，因此这个接口刻意不做 Origin/CSRF 校验——签名 token 本身就是授权凭证。

## 三、签名契约（Python ↔ Worker 必须严格一致）

```
token = "<exp>.<sig>"
exp   = Unix 秒级时间戳（now + UNSUB_TTL_DAYS，默认 180 天）
sig   = hex( HMAC_SHA256(UNSUB_SECRET, "unsub:<小写邮箱>:<exp>") )[:32]
URL   = <生效对外地址>/unsubscribe?email=<urlencode(邮箱)>&token=<token>
        生效对外地址 = PUBLIC_BASE_URL || https://<CUSTOM_DOMAIN> || <WORKERS_DEV_URL>
```

| 实现 | 文件 |
|---|---|
| Python 签发 | `yds/unsub.py` → `make_email_token()` / `build_unsubscribe_url()` |
| Worker 校验 | `worker/src/security.ts` → `verifyUnsubToken()` |
| 契约自测 | `python -m yds.selftest` + `cd worker && npm test` |

校验规则：

- token 必须是 `<1-12位数字>.<32位小写hex>`
- `exp` 必须**严格大于**当前时间，且不超过 `now + (UNSUB_TTL_DAYS + 30天)`
- 签名消息里的邮箱统一小写；改 URL 里的 email 即校验失败
- 可选：填了 `UNSUB_SECRET_PREVIOUS` 时，新旧密钥都能验签，便于平滑轮换

> **历史缺陷（已修复）**：早期 Python 用 `exp=0` 表示「永久有效」，而 Worker 把 `0` 判成已过期，
> 导致**所有按邮箱退订链接失效**，唯一能用的反而是危险的全局退订。现在双方统一签发带过期时间的
> 按邮箱 token，并显式拒绝 `exp=0`。改任何一端都要同时跑两边的自测。

## 四、需要填的配置

### Cloudflare（Dashboard → Variables and Secrets）

| 类型 | 名称 | 值 |
|---|---|---|
| Secret | `UNSUB_SECRET` | `openssl rand -hex 32` |
| Secret | `UNSUB_SECRET_PREVIOUS` | 可选，轮换期的旧密钥 |
| Variable | `CUSTOM_DOMAIN` | 自定义域名（如 `notice.example.com`），退订 URL 自动派生 |
| Variable | `WORKERS_DEV_URL` | 没绑自定义域时填 workers.dev 地址；同时进 CSRF 白名单 |
| Variable | `UNSUB_TTL_DAYS` | `180` |
| Variable | `MAIL_TO` | 站长邮箱（退订通知） |

### GitHub Actions Secrets

| Secret | 值 |
|---|---|
| `CUSTOM_DOMAIN` | **与 Cloudflare 同值**，退订 URL 自动派生 |
| `WORKERS_DEV_URL` | 兜底，可选 |
| `UNSUB_SECRET` | **必须与 Cloudflare 完全一致** |
| `UNSUB_TTL_DAYS` | 与 Cloudflare 同值 |

**两边 `UNSUB_SECRET` 不一致 → 所有退订链接返回 400**，这是最常见的故障原因。
`UNSUB_URL` 已由域名自动派生，新部署不用填；旧部署若单独填过仍会作为显式覆盖生效。
换自定义域名时只需改 `CUSTOM_DOMAIN` 并跑一次 `npm run sync-config`，邮件里的退订链接会自动跟着变。

## 五、验证

```bash
# 1. 确认 Worker 活着
curl https://<你的Worker>/health

# 2. 本地跑一次完整流程但不发信，日志里会打印退订链接示例
.venv/bin/python -m yds.selftest
.venv/bin/python -m yds --dry-run

# 3. 手动触发一次 Actions，收到邮件后点底部「一键退订」
#    GET → 确认页「确定要退订吗？」
#    POST → 「已退订」
```

退订成功的表现：`sub:<邮箱>` 记录被删除、`meta:count` 减一、`user:<邮箱>` 仍在。可核对：

```bash
cd worker
npx wrangler kv key list --binding SUBS --prefix "sub:"
```

想恢复订阅：重新登录控制台即可（首次登录发现 `sub:` 不存在会自动重建）。

## 六、安全设计

- **一人一签**：token 绑定具体邮箱，无法拿自己的链接退订别人
- **有限有效期**：默认 180 天，过期即失效，历史链接可自然作废
- **双密钥轮换**：`UNSUB_SECRET_PREVIOUS` 让轮换期间旧链接仍可用，轮换完成后清空即可
- **GET/POST 分离**：防邮件客户端预抓取误退订
- **最小权限**：Worker 不持有 GitHub Token，退订不再影响其他订阅者，也不影响定时任务
- **错误不回显**：校验失败只给通用文案，不暴露签名细节

## 七、常见问题

**退订页显示「这个链接不能用了」？**
按顺序检查：① `UNSUB_SECRET` 两边是否一致；② 链接是否超过 `UNSUB_TTL_DAYS`；③ 两边 `UNSUB_TTL_DAYS` 差异是否过大；④ 邮件是不是旧版本代码发出的（旧版 `exp=0` 链接现在会被拒绝，属预期行为，重发一封新邮件即可）。

**不部署 Worker 行不行？**
行。不设置 `UNSUB_SECRET`，或 `CUSTOM_DOMAIN` / `WORKERS_DEV_URL` / `PUBLIC_BASE_URL` 都没配导致派生不出地址时，邮件不显示退订按钮，其余功能不受影响。但批量邮件场景下强烈建议部署，否则会影响送达率（Gmail / Yahoo 对一键退订有要求）。

**为什么不再往仓库开 Issue 留痕？**
旧版为了留痕给 Worker 发了具备 Actions + Issues 写权限的长期 PAT，收益远小于风险。现在站长会收到一封退订通知邮件，足够回溯。
