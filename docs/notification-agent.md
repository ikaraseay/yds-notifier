# 通知 Skill 的运行与上线

`skills/catalog.json` 提供模板。Worker 将配置、共享来源、分类、个人偏好和规则任务保存在 D1。组主编辑草稿，公开审核通过后订阅者使用公开版本。管理员从通知组后台管理研电赛共享来源。

Python 网站组任务使用原有的安全试抓器读取 HTML、RSS 和 JSON。它对比基线、摘要变化并按当前 Skill 的标签分类。未完成的模型分析保留原基线以便重试。首次试抓会生成监控提示词，并要求模型给出样本中的逐字依据，通过后才生效。Worker 仅接受配置中存在的来源和标签，同时提交检查结果、通知记录和待发邮件。个人通知记录和邮件按当前偏好筛选。个人日历仅收录原文可核实日期的网站更新。

内置研电赛的自定义网址使用同一个试抓器。Worker 记录变化后，研电赛爬虫通过认证接口读取这些通知并交给现有赛事投递器。网站组投递器跳过 `yds`，避免同一事件同时进入两种邮件任务。个人赛事偏好继续读取现有 KV 数据，保留原日历地址和赛事通知 ID。

规则任务使用 `SKILL_QUEUE` 和 Workers AI。创建者或管理员提交改进建议后立即入队，不等待下一轮抓取。审核读取当前配置版本和真实样本，候选规则必须通过独立审核并提供原文引文，且只能改写提示词或摘要规则，不能新增网址、修改分类或权限。数据库写入要求版本仍然匹配，配置已更新则任务标记为过期。队列失败会重试，达到重试上限后任务标记失败，消息进入死信队列。建议页面保留每次变更的原规则、候选规则和依据，可恢复上一版。

## 发布顺序

1. 备份 D1 并应用 `cloudflare/group-migrations`。已有安装可运行 `bash scripts/ops.sh groups-setup` 应用增量迁移。迁移不会创建待发邮件。
2. 在 Worker 所属账户中创建 `notification-skill-rules` 和 `notification-skill-rules-failed` 队列，确认该账户可使用 Workers AI。
3. 部署 Worker 和同版本 Python 任务。两者的 `GROUP_RUNNER_TOKEN` 或兼容的 `SUBSCRIBE_API_TOKEN` 须一致。
4. 用私有测试组完成一次基线试抓和一次更新。核对通知记录、实际收件人、队列审核结果与个人日历，再为公开组启用监控。
